v2.4.15-beta
-------------
- 修正工作模式 1 組合 1 的雙語字幕語系定義：備用軌固定為「簡體中文／繁體中文 + 原語言（English／Japanese／Korean）」；不再把新加入的雙語軌標記為 `und`。
- 依雙語字幕來源路徑／檔名識別簡繁：支援 `ZH-TW_EN`、`ZH-CN_JA`、`ZH-TW_KO`、`zh-Hant`、`zh-Hans`、Traditional／Simplified Chinese 等標記。
- 若來源缺少簡繁標記、同時標記簡體與繁體、或明確原語言與本批主要語言 profile 不符，該集安全停止，不推測字幕內容、不錯配集數。
- 封裝時使用 `zh-TW`／`zh-CN` BCP 47 語言標記，軌道名稱包含中文變體及原語言；雙語 ASS／SSA／SRT 保持為單一完整字幕軌，不拆分、不重新編碼；主要 EN／JA／KO 字幕仍 Default Yes，雙語備用軌 Default No。
- 雙語旁掛檔依簡繁及原語言命名，例如 `.zh-tw-en.ass`、`.zh-cn-ja.ass`、`.zh-tw-ko.ass`；舊有只有通用中文標記的軌道維持 `.zh`。批次預檢同步保護 locale-specific 檔名，避免覆蓋。
- 新增 14 項雙語回歸測試，涵蓋簡繁識別、EN／JA／KO 原語言配對、衝突拒絕、mkvmerge 參數、旁掛匯出及既有檔案保護；GitHub Actions Python 編譯通過，完整 unittest 146/146 通過，FFmpeg SRT／ASS pipe smoke test 通過。真實 macOS + MKVToolNix 端到端測試仍待實機執行。
- 新增 GitHub Actions 自動執行 Python 編譯與完整 unittest 套件；真實 macOS + MKVToolNix 端到端仍以使用者裝置驗證為準。

- Python 語法檢查通過；完整單元測試 132/132 通過。建置環境未安裝 MKVToolNix，真實 MKVToolNix macOS 端到端測試仍需在使用者環境執行。

v2.4.11-beta
-----------
- 修正單一 AAC 音訊軌 MP4 -> MKV 封裝時，來源 MP4 的 QuickTime sample-size 欄位回報 `audio_bits_per_sample=16`，但輸出 Matroska 未提供可選 `BitDepth`（None）所造成的跨容器誤判。
- Matroska RFC 9559 將 Audio BitDepth 定義為每樣本位元數，並註明主要用於 PCM；對 AAC 這種壓縮格式，該欄位可不出現。
- 僅接受來源／輸出各恰好一條音訊軌、來源值恰為 16、輸出值缺失、來源 CodecID 缺失、輸出 CodecID 恰為 `A_AAC`，且來源／輸出 codec 描述相同並明確為 AAC 的情況。
- 其他位深值、明確來源 CodecID、多音訊軌、非 AAC、輸出明確提供不同 BitDepth 等情況仍嚴格拒絕。
- FFprobe 的 codec_name、Profile、sample_rate、channels、channel_layout、bits_per_sample、bits_per_raw_sample 仍嚴格比對；音訊封包數及完整影音解碼不放寬。
- 新增 AAC Matroska BitDepth 正規化回歸測試；真實 MKVToolNix v104.0 端到端測試仍需在使用者 Mac 完成。

v2.2.0-beta
